## 这份规范解决什么问题

写 QMT 策略的难点从来不是「不会写均线」，而是——**同一套逻辑，换个人写就换了样；让 AI 写，AI 每次给你一个不同的架构**。

于是你会遇到这些事：

| 场景 | 没有规范时 |
|---|---|
| 让 AI 写策略 | 每次结构都不同，分层混乱，今天有 `Manager` 明天有 `Pipeline`，无法维护 |
| 换人接手 | 文件头没写清楚，外部文件、生命周期全靠口口相传 |
| 策略重启 | 内存里的防重标志丢了，同一只票当天买了两笔 |
| 界面关了策略 | checkBox 注入的是字符串 `'False'`，Python 判定为真，**策略照常下单** |
| 到了涨停 | 忘了分板块算涨停价，买在封板板上 |
| 复盘时看日志 | 成交方向全是「买」—— 因为股票场景下 `m_nDirection` 恒为 48 |
| 交付前检查 | 没有统一清单，靠人肉通读 3000 行代码 |

**这份规范把上面每一件事都变成一条可勾选的硬性条款。**

## 核心特性

### 1. L0–L6 七层骨架，代码从上层往下长

策略文件必须按固定顺序组织，每层职责单一、不得越界：

```
L0 契约层   文件头 docstring：外部文件、生命周期、API 证据、交易规则
L1 配置层   账号 / 开关 / 预算 / 上限 / 文件路径常量
L2 状态层   模块级全局变量 + 缓存字典（禁止挂在 ContextInfo 上）
L3 基础设施 日志 / CSV 读写 / 代码归一化 / 交易日历 / 行情订阅
L4 行情指标 Quote 类：run_full(启动) + run_tick(每 tick) + summary()
L5 信号层   扳机模型 + 统一信号字典 + 前置两道锁
L6 执行层   判据过滤 → 下单 → 状态落盘
```

配套给出**顶层 19 个 section 的固定顺序表**，每行标注所属层、内容要点、对应条款 —— AI 照着往下写，人也能逐行核对。

### 2. 生命周期契约：init / after_init / handlebar 各能干什么

明确写出**允许矩阵**与**禁止矩阵**，把 QMT 的经典坑标出来：

- `init` 里调 `get_trading_dates` → 官方文档明确此时不可用
- `init` 里批量拉 K 线 → 行情尚未就绪
- `handlebar` 里抛异常 → 中断 QMT 调度，策略静默失效
- `handlebar` 7 步执行顺序固定，快照归属唯一

### 3. 四道防重锁：把「重复买入」拆成四层独立防线

这是本规范最核心的防护设计。每一道锁拦截的场景不同，**缺一层就有一类漏买或重买**：

| 锁 | 拦截时机 | 拦截的场景 | 只装它会漏掉 |
|---|---|---|---|
| 锁 1 · 信号层短路 | 判定前 | 同标的同扳机在本次运行内重复触发 | 同标的被**不同扳机**先后触发 |
| 锁 2 · 标的禁用 | 判定前 | 已买入后其它信号再次到达 | 禁用写盘失败时无兜底 |
| 锁 3 · 状态表落盘 | 下单前 | 策略重启 / 崩溃 / 多实例并发 | 跨档位判断易漏 |
| 锁 4 · 持仓 + 活动委托 | 下单前 | 委托已提交未成交 → 二次下单 | 在途委托重复下单、超买 |

规范明确要求：**锁 1 与锁 2 必须同时存在**，缺一不可。

### 4. 三级条款约束 + 112 项交付自检

| 标记 | 含义 |
|---|---|
| **【必须】** | 强制，不可协商，违反即返工 |
| **【建议】** | 默认做法，偏离需说明理由 |
| **【禁止】** | 红线，违反可能造成实盘资损 |

交付前走完 **12 组 Checklist（共 112 项）**，每条都能客观判定通过 / 不通过。

### 5. 23 条硬性禁令：都是真实踩过的坑

每一条都写明「禁令 → 原因 → 替代方案」，例如：

- 禁止在 `ContextInfo` 上挂自定义属性 → 官方说会被回滚，重启后重复下单
- 禁止直接用界面注入的布尔值 → 字符串 `'False'` 是真值，关了开关照样下单
- 禁止只靠单层机制防重复买入 → 见上文四道锁
- 禁止用 `m_nDirection` 判定买卖方向 → 股票场景恒为 48，卖出全被记成「买」
- 禁止用 `base_close` 算涨幅 → 基准日可能是任意历史日，涨幅基准会错
- 禁止把提交异常当作「未提交」立即重下 → 委托可能已到达交易所，会重复买

### 6. 证据驱动：找不到官方依据就写「待确认」

所有引用的 QMT 官方接口必须在注释中给出**文档链接或官方示例路径**。找不到证据时：

1. 写 `# 待确认: <用途>，未找到官方文档佐证`
2. **停下提问**
3. **禁止**凭记忆编造接口签名与参数顺序

### 7. 交易规则知识库：客观规则统一维护

分板块涨跌幅表（含 ST 创业板 / 科创板仍为 20% 这类易错项）、涨停价向下截断算法、委托状态码映射表、买卖方向标志 —— 全部封装为单一函数，改一处生效一处。

## 适用与不适用

**适用**

- 运行在 QMT 模型交易 / 策略交易环境的 Python 策略文件
- **只买不卖**的买入型策略
- 「股票池 → 信号判定 → 自动下单」驱动模式的策略

**不适用**

- 回测框架（backtrader / vectorbt 等）代码
- 选股脚本、行情下载脚本等非交易进程脚本
- 网格 / 套利 / 多标的组合择时等需要复杂仓位管理的策略（超出本骨架能力，需另立规范）
- 卖出逻辑 —— V1.0 未覆盖，见附录 C.1

规范只管**结构、留痕、可复盘**；具体信号条件、阈值、预算是使用者的业务决定，规范不管数值。

## 设计原则

1. **框架优先，零重复造轮子** —— QMT 已提供的能力一律直接调用官方接口。禁止自建行情框架、订单管理器、事件总线、持久化框架、缓存框架。
2. **最小改动，不新增抽象层** —— 只允许通过官方扩展点接入（基类、配置、callback、registry 等）。
3. **证据驱动，禁止编造** —— 每个引用的官方 API 必须有文档链接或示例路径佐证。
4. **行为可复盘** —— 每个决策都留痕：触发原因、跳过原因、委托状态、成交明细，一行可读。
5. **资金安全优先** —— 涉及下单、重复触发、资金占用的条款一律用【必须】/【禁止】级约束。
